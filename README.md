# blog-tanstack — deco.cx Blog Template

A production-ready blog template built with [TanStack Start](https://tanstack.com/start), [deco.cx](https://deco.cx) CMS, and Tailwind CSS v4. Supports server-side rendering, reading progress, search, categories, authors, and a magazine-style layout.

## Features

- **Magazine layout** — hero cover story, duo feature grid, and article feed on the home page
- **Full-text search** — server-side filtered search with highlighted matches
- **Categories & Authors** — filtered listing pages with paginated results
- **Reading progress bar** — visible on individual post pages
- **Hero scroll header** — transparent header transitions to white/blur on scroll over post cover images
- **Responsive** — mobile-first with a slide-out drawer menu
- **CMS-powered** — all content is saved blocks in `.deco/blocks/`, edited by hand or in the Deco site editor (`deco serve`)

## Getting started

### Requirements

- [Bun](https://bun.sh) (recommended) or Node.js 24+

### Install and run

```sh
bun install
bun run dev        # predev runs `deco schema && deco content`
```

Open [http://localhost:5173](http://localhost:5173). To edit content in the site editor, run `npx @decocms/blocks serve` beside the dev server and open the link it prints.

### Build, check and test

```sh
bun run build      # prebuild runs `deco schema && deco content && deco check`
bun run typecheck
bun run test
```

## Project structure

```
.deco/
  index.ts             # the block map: every block type content can call, with its v7 names as aliases
  blocks/              # content: pages, posts, categories, authors, site settings, CMS (analytics, telemetry, preview hosts)
  schema.gen.json      # generated by `deco schema` (committed)
  blocks.gen.ts        # generated by `deco content` (gitignored)
src/
  cms.ts               # createCMS({ blocks, content })
  open-page.server.ts  # matchRoute + one block promise per section (unknown URLs render /404 with a 404)
  page.functions.ts    # the server function the routes call
  routes/              # __root (layout, analytics), / and /$ (CMS pages), sitemap.xml
  views.tsx            # descriptor -> section component
  blocks.server.ts     # server-side props for sections (URL, site and blog settings, search index)
  seo/                 # the page `seo` blocks (post and topic SEO with their JSON-LD) and the head tags they produce
  sdk/blog/            # rendering shared by the sections: blocks.tsx (post block registry, default x custom),
                       # toc.ts, jsonLd.ts (schema.org for the listing pages), format.ts, scripts.ts
  components/blog/     # shared UI pieces (AuthorAvatar)
  utils/site-config.ts # site and blog settings -> SiteConfig (publisher, canonical origin)
  blog/, vendor/blog/  # blog loaders and the blog app's default post blocks (vendored from @decocms/apps-blog)
  sections/Blog/       # the blog UI sections, markup only
  sections/Blog/Post/  # this template's post blocks (site/sections/Blog/Post/*)
  edge/, worker-entry.ts  # page cache profiles, device split, security headers (Cloudflare Worker)
```

## Blog settings

The blog's settings live in `.deco/blocks/deco-blog.json` (a `blog-settings` block): `pageSlug`,
`categorySlug`, `canonicalBaseUrl` (origin used for canonicals and JSON-LD),
`publisher` and `seo` (the title and description templates of the post and topic pages).

### Post content blocks

`post.sections` accepts two families of blocks, distinguished by `__resolveType`:

| Family  | Block map name     | v7 name (saved content)              | Rendered by                                                  |
| ------- | ------------------ | ------------------------------------ | ------------------------------------------------------------ |
| default | `post-default-*`   | `blog/sections/blocks/<Name>.tsx`    | the blog app's component (vendored in `src/vendor/blog/sections/blocks/`) |
| custom  | `post-*`           | `site/sections/Blog/Post/<Name>.tsx` | this template (`src/sections/Blog/Post/`)                    |

The mapping lives in `src/sdk/blog/blocks.tsx`. To add a custom block, create it in
`src/sections/Blog/Post/`, register it in `CUSTOM_BLOCKS`/`CUSTOM_TYPES` and add it to `.deco/index.ts`.

## Content management

Posts, categories and authors are saved blocks in `.deco/blocks/`. Edit them in the site editor (`npx @decocms/blocks serve`) or by hand.

### Adding posts

Create `.deco/blocks/collections%2Fblog%2Fposts%2Fyour-post.json`:

```json
{
  "name": "collections/blog/posts/your-post",
  "__resolveType": "blog/loaders/Blogpost.ts",
  "post": {
    "title": "Your Post Title",
    "slug": "your-post",
    "date": "2025-01-01",
    "excerpt": "Short description…",
    "image": "https://images.unsplash.com/photo-…?w=1280&h=720&fit=crop&q=80",
    "authors": [{ "name": "Author Name", "email": "author@example.com" }],
    "categories": [{ "name": "Engineering", "slug": "engineering" }],
    "sections": [
      { "__resolveType": "post-heading", "level": "h2", "text": "First steps" },
      { "__resolveType": "post-paragraph", "html": "<p>…</p>" }
    ]
  }
}
```

A post's `sections` are its body blocks, the `post-*` sections of `.deco/index.ts`. Older posts store them under their v7 names (`site/sections/Blog/Post/Heading.tsx`); both render the same.

Then run `npx @decocms/blocks content` (or restart the dev server) and `npx @decocms/blocks check`.

### Adding categories / authors

Follow the same pattern with `collections%2Fblog%2Fcategories%2F<slug>.json` (`blog/loaders/Category.ts`) and `collections%2Fblog%2Fauthors%2F<slug>.json` (`blog/loaders/Author.ts`).

## Notes on the v8 migration

- **Dependencies.** `@decocms/blocks` is installed from npm (`^8.1.0-next.3`, the `next` dist-tag) and pinned by the committed `bun.lock`, so `bun install` is all you need; no local link. The v8 line has no `@decocms/start` or `@decocms/apps` counterpart: everything those packages used to provide lives in this site.
- **Blocks are awaited before the page renders** (`src/open-page.server.ts`), a deliberate exception to the TanStack Start guide, which keeps block promises unawaited. This site's blocks only read the content in memory and settle at once, and rendering them all in the first HTML chunk keeps the hero image's preload in the head, as on v7. `test/pages.test.ts` covers it. A block that starts fetching upstream should stop being awaited there.
- **Edge cache.** `src/worker-entry.ts` caches HTML pages and GET server functions (the page data of client-side navigations) in the Cloudflare Cache API, as v6 did, split by device and keyed by deployment. v6's `X-Cache-Version`, `X-Cache-Reason` and `X-Cache-Segment` headers, `POST /_cache/purge` and `?asJson` are gone; a deploy changes the cache key, so content changes never need a purge. `/deco/_liveness` still answers `OK`.
- **Content.** `website/functions/requestToParam.ts` (v7's "the last path segment" function) was rewritten in content to the page's route `param` (`/:slug`, `/topics/:slug`, `/authors/:email`), a documented content migration that gives the same values.
